CNSA 2.0 explained

The NSA’s Commercial National Security Algorithm Suite 2.0, what it requires and when.

CNSA 2.0, the Commercial National Security Algorithm Suite 2.0, is the set of quantum-resistant algorithms the US National Security Agency requires for national security systems (NSS). Announced in September 2022, it sets the path for moving classified and mission-critical systems to post-quantum cryptography by 2035.

Who must comply with CNSA 2.0?

CNSA 2.0 applies to national security systems: those that handle classified information or support military, intelligence and other critical government missions. In practice it also affects the defense industrial base, federal contractors and the vendors whose products are sold into those systems. Many commercial organizations use CNSA 2.0 as a benchmark because it is the most specific government timeline available.

CNSA 2.0 algorithms

  • ML-KEM-1024 (FIPS 203) for key establishment.
  • ML-DSA-87 (FIPS 204) for digital signatures.
  • LMS and XMSS (NIST SP 800-208) stateful hash-based signatures for software and firmware signing.
  • AES-256 for symmetric encryption.
  • SHA-384 or SHA-512 for hashing.

CNSA 2.0 uses the highest security parameter sets. That differs from many commercial deployments, which commonly start with ML-KEM-768. See our guide to the NIST PQC standards for background on each algorithm.

CNSA 2.0 timeline

The NSA set dates by which each category should support and prefer CNSA 2.0 algorithms, and dates by which it should use them exclusively:

  • Software and firmware signing: support and prefer by 2025, use exclusively by 2030.
  • Web browsers, servers and cloud services: support and prefer by 2025, use exclusively by 2033.
  • Traditional networking equipment such as VPNs and routers: support and prefer by 2026, use exclusively by 2030.
  • Operating systems: support and prefer by 2027, use exclusively by 2033.
  • Niche equipment and constrained devices: support and prefer by 2030, use exclusively by 2033.
  • Custom applications and legacy equipment: update or replace by 2033.

The NSA has also said that new NSS acquisitions should be CNSA 2.0 compliant from January 2027, with all NSS quantum-resistant by 2035. Check the NSA’s current CNSA 2.0 guidance for updates before setting contract dates.

Preparing for CNSA 2.0 compliance

  1. Map which of your products and systems fall into each CNSA 2.0 category.
  2. Build a cryptographic inventory and identify every use of RSA, ECC and smaller key sizes.
  3. Prioritize firmware and code signing, since its exclusive-use deadline is earliest. See post-quantum PKI and code signing.
  4. Confirm that HSMs and cryptographic modules can support CNSA 2.0 algorithms with FIPS 140-3 validation.
  5. Add CNSA 2.0 requirements to supplier contracts and product roadmaps.
