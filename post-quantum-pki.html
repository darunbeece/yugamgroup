Post-quantum PKI

Getting certificate authorities, certificates and code signing ready for quantum-safe cryptography.

Public key infrastructure (PKI) issues the digital certificates that prove the identity of websites, servers, devices, users and software. Today almost every certificate is signed with RSA or ECDSA, both of which a quantum computer could break. Post-quantum PKI replaces those signatures with quantum-safe algorithms such as ML-DSA, without disrupting the systems that rely on them.

Why PKI is central to post-quantum readiness

If an attacker can forge a certificate authority’s signature, they can impersonate any server or sign malware that devices will trust. Root certificates often live for 20 years or more and are embedded in devices, browsers and operating systems, so a CA created today may still be in use after Q-Day. That makes PKI one of the longest lead-time items in any PQC migration.

Quantum-safe certificate options

  • Pure post-quantum certificates use ML-DSA (FIPS 204) or SLH-DSA (FIPS 205) signatures and keys. They are the end goal but need every relying party to support the new algorithms.
  • Hybrid certificates carry both a classical and a post-quantum key or signature, so older systems can keep validating with RSA or ECDSA while updated systems check the post-quantum one.
  • Composite certificates combine a classical and a post-quantum algorithm into a single key and signature that is only valid if both verify. The IETF is standardizing composite ML-DSA, and several CA products already support it.
  • Parallel PKIs run a separate post-quantum hierarchy alongside the existing one, issuing two certificates where needed.

The right choice depends on which applications validate your certificates and how quickly they can be updated. Most enterprises will use more than one approach during the transition.

Post-quantum code signing

Software and firmware signatures are especially important because devices may verify them for many years. Stateful hash-based signatures (LMS and XMSS, NIST SP 800-208) are already approved for firmware signing and required by CNSA 2.0 for national security systems, while ML-DSA suits general code signing. Devices shipping today should have a path to verify post-quantum signatures, or they may need to be replaced later.

Steps to a quantum-safe PKI

  1. Inventory every CA and certificate, including private CAs, cloud certificate services and certificates embedded in devices. See cryptographic inventory.
  2. Automate certificate lifecycle management. Short-lived, automatically renewed certificates make it far easier to switch algorithms. Shorter public TLS certificate lifetimes, agreed by the CA/Browser Forum, are pushing the same way.
  3. Check HSM support for ML-DSA and SLH-DSA key generation before planning new CAs. See HSM key management.
  4. Build a test PKI with post-quantum and composite certificates and test it against your applications, load balancers, VPNs and devices.
  5. Plan new root and issuing CAs with quantum-safe algorithms, and schedule cross-signing and trust store updates.
